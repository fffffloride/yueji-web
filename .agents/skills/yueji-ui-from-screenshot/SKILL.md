# 悦己截图还原页面

把临时参考截图转成可交付的悦己页面。保持业务逻辑、真实接口和五个 Tab，不复制参考产品的品牌素材。

## 必读

开始前完整读取：

- `AGENTS.md`
- `docs/改造计划.md`
- `docs/superpowers/specs/2026-08-24-screenshot-fidelity-workflow-design.md`
- `src/styles/variables.scss`、`src/styles/common.scss` 和相关现有页面/组件

服务端与管理端默认是同级仓库：`../yueji-backend`、`../yueji-oss`。不要写入任何本机绝对路径。

## 工作清单

按顺序跟踪，未通过当前门槛不要进入下一步：

```text
- [ ] 1. 预检项目与工作区
- [ ] 2. 收集截图和交互状态
- [ ] 3. 拆解布局、状态和字段
- [ ] 4. 确认短设计
- [ ] 5. 最小实现
- [ ] 6. H5 双尺寸交互验收
- [ ] 7. 工程检查与微信构建
- [ ] 8. 精确提交和交付报告
```

## 1. 预检

1. 运行 `git status --short`，记录用户已有改动，禁止覆盖或夹带。
2. 搜索页面入口、公共组件、主题变量、接口类型和相邻实现；优先复用。
3. 确认截图中的字段是否已由真实接口返回。只有字段确实缺失时才修改同级后端和管理端。
4. 找不到同级仓库、后端不能启动或缺少会改变结果的截图时，先说明阻塞；其他情况合理假设并继续。

## 2. 截图输入

- 接受 Codex 附件或临时绝对路径；先查看原图和像素尺寸。
- 参考原图、裁剪图、叠加图和临时验收截图默认不复制到仓库、不提交 Git。
- 每张图记录入口态或触发动作，例如“点击二级菜单后”“筛选开启”“滚动到底部”。
- 优先覆盖入口、中部滚动、底部、选中、空、失败、禁用和长内容；通用状态沿用现有组件时无需重复索图。
- 临时图片在另一台电脑不可用时，请用户重新附加，不伪造参考图。

## 3. 拆解与设计门槛

1. 按 `750 / 截图宽度` 换算 rpx，记录固定区、滚动区、吸顶区、图片比例、间距、字号和截断。
2. 建立三张最小清单：布局结构、交互状态、真实字段来源。
3. 颜色只映射到现有 `$color-*`、`--yj-*` 和 Wot 主题变量；品牌文案、Logo、图片使用悦己内容。
4. 保留既有路由、鉴权、金额单位和业务流程。不要为截图静态写死业务数据。
5. 若本轮设计尚未确认，先给出推荐方案、关键取舍和验收标准，取得用户确认；已确认的设计不要重复讨论。

## 4. 最小实现

- 页面继续使用 `YjPage`、`RoutePath`、`navigate()`、现有 API 层、公共空态和加载态。
- 样式使用现有 SCSS/BEM 与 rpx；优先 CSS 和小程序原生 `scroll-view`，不新增库。
- 共同行为只在已有共享入口修复；不要为一个调用方复制组件或工具。
- 非平凡分支或滚动计算留一个最小可运行自检，不建立额外测试框架。
- 首次失败、切换失败、空数据、图片失败和重复提交按实际风险处理，不为了少写代码移除必要错误处理。

## 5. H5 双尺寸验收

真实数据需要后端时，在 `../yueji-backend` 启动 `pnpm start:dev`；然后在本仓库运行：

```bash
pnpm dev:h5 --host 127.0.0.1
```

使用可用的浏览器控制能力完成：

1. 打开目标 H5 路由，先读取页面结构再操作。
2. 分别使用 `375×812` 和 `430×932` 视口；验收后恢复浏览器视口。
3. 截取入口态，并按截图说明实际点击、滚动、切换筛选和触发空/失败状态。
4. 同时验证“点击菜单滚到内容”和“滚动内容更新高亮”；横向菜单必须保持活动项可见。
5. 检查固定栏、吸顶、底部留白、长标题、图片失败、控制台错误和网络失败表现。
6. 视觉以几何、层级、裁切和交互为准；真实图片和文案不要求与参考产品相同，关键布局目标误差约 `4rpx`。

浏览器控制不可用时，把以上六项转换为人工勾选清单，并明确标注“未自动验收”。

## 6. 工程检查

先运行本轮新增的最小自检和触及文件的非修复型 lint，再运行统一门槛：

```bash
pnpm verify:ui
```

`verify:ui` 必须保持非修改型，并覆盖 ESLint、Stylelint、类型检查、已有 UI 自检、H5 构建和微信小程序构建。新增通用 UI 自检时把它加入该命令。

每页强制门槛到 H5 交互和 `mp-weixin` 构建为止；微信开发者工具和真机是发布前人工门槛，不声称已经自动完成。

## 7. Git 与交付

1. 再次运行 `git diff --check` 和 `git status --short`。
2. 只暂存本轮明确文件；多仓库分别提交，不提交 `.env*` 密钥、构建产物、临时截图或用户无关改动。
3. 使用 Conventional Commit；一个模块保持独立、可回退。
4. 最终最多报告：完成内容与提交号、通过的检查、仍需用户/微信工具完成的门槛。
