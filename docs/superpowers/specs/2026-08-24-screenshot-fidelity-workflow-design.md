# 悦己小程序截图高保真还原设计

日期：2026-08-24  
状态：已确认

## 1. 目标

以同一个参考小程序的截图为视觉依据，高保真还原悦己小程序各模块。悦己现有五个 Tab、阶段 2–7 业务流程和真实接口保持不变；参考对象只决定布局、视觉层级、间距和交互表现。

高保真不包含复制对方的 Logo、品牌名称、宣传文案、商品图片或其他专有素材。所有品牌内容替换为悦己内容，颜色按悦己现有主题变量映射。

首个校准页面为商品分类列表。校准完成后，按交易依赖依次处理阶段 3–7。

## 2. 固定原则

- 使用现有 uni-app、Vue 3、Wot Design、Pinia 和请求封装，不换技术栈。
- 复用现有主题变量、页面骨架、空状态和已有业务组件；只在实际重复时抽组件。
- 参考页面的几何结构与交互尽量一致，品牌色统一映射到悦己墨绿主题。
- UI 展示的业务字段必须来自真实接口，不为截图制造静态假数据。
- 后端缺字段时先补最小字段和管理入口，再实现页面。
- 每个模块独立完成截图采集、实现、视觉校准、功能验收和提交。
- 不提前实现阶段 8–9 或参考小程序中悦己没有规划的功能。

## 3. 主题映射

继续使用项目现有配置：

- 主色：`#2D5A3D`
- 深色：`#1A3A28`
- 浅色：`#4A7C59`、`#6B9B7A`
- 页面背景：`#F7F8FA`
- 组件库主题、TabBar 选中色和全局 CSS 变量均以现有配置为准。

参考截图中的绿色、选中态、按钮、描边、标签和强调文字，按语义映射到上述变量；不直接散落新的品牌色硬编码。

## 4. 每个模块的协作闭环

1. **收截图**：用户按最小状态清单提供电脑原始截图，并说明每张图的触发动作。
2. **拆页面**：识别固定区、滚动区、吸顶区、列表项、浮层和安全区。
3. **量尺寸**：按截图宽度比例换算到 750rpx，记录宽高、间距、字号、圆角和图片裁切方式。
4. **补状态**：列出截图已覆盖和未覆盖的正常、选择、空、加载、失败、禁用及边界状态。
5. **对字段**：逐项确认页面内容来自哪个真实接口；缺失字段只做必要的后端和管理端改动。
6. **做页面**：先完成主要布局和交互，再接完整异常状态；不单独制作不可交互的静态稿。
7. **做对比**：在相同逻辑宽度下截实现图，与参考图并排并进行半透明叠加校准。
8. **验功能**：验证点击、滚动、吸顶、返回、刷新、分页、禁用和错误恢复。
9. **交付**：用户确认该批视觉后，运行检查并独立提交。

截图不要求来自手机。当前 828px 宽截图直接按比例归一到 750rpx；后续尽量保留完整页面区域，不裁掉菜单、吸顶栏、浮层或列表边界。

## 5. 最小截图规范

每个页面优先提供：

- 入口态：刚进入页面、未操作。
- 滚动态：顶部、中部、底部。
- 选择态：菜单、Tab、筛选和按钮的选中/禁用样式。
- 浮层态：弹窗、抽屉、选择器、Toast 展开状态。
- 边界态：长标题、多标签、极端价格、无库存或不可操作项。
- 触发说明：一句话说明“点了什么”或“滚到了哪里”。

普通骨架屏、通用空状态、网络失败和通用确认框默认沿用悦己现有组件。参考小程序存在明显特殊设计时才补对应截图。

截图可以分批提供，无需一次收齐全项目。每批开始时只索取本批需要的页面和状态。

## 6. 模块顺序与截图重点

### 6.1 校准批：商品分类列表

- 顶部入口和第一组商品。
- 滚入其他一级分类后的左侧高亮。
- 二级菜单不同选项的高亮与横向位置。
- “仅查看疼痛友好项目”关闭、开启有结果、开启无结果。
- 长商品名、副标题、多标签、价格与优惠差额。
- 列表底部和没有更多。

用户已经提供顶部入口、一级联动和二级联动截图。实现前只需补筛选开启和列表底部。

### 6.2 阶段 3：交易主链路

- 商品详情：默认、SKU 选择、无库存、数量、底部操作栏。
- 购物车：空、部分选中、全选、改数量、删除、失效商品、去结算。
- 订单确认：购物车来源、立即购买来源、提交中、创建失败。
- 订单列表：不同状态 Tab、空列表、翻页、可用操作。
- 订单详情：待付款、已付款、已取消及底部动作。

### 6.3 阶段 4：支付与个人中心

- 支付结果：成功、处理中、失败。
- 我的：未登录、已登录、订单状态入口和统计。

### 6.4 阶段 5：会员权益

## 7. 商品分类列表校准设计

### 7.1 页面结构

- 路由继续使用 `pages/product/index`。
- 主内容为固定高度的左右两栏，左栏沿用现有 `176rpx` 宽度。
- 左侧是独立纵向 `scroll-view`，显示一级分类。
- 右侧只有一个纵向 `scroll-view`，所有一级和二级商品分区连续排列。
- 顶部显示“仅查看疼痛友好项目”开关。
- 当前一级分类有二级分类时，显示可横向滚动的二级菜单并吸顶。
- 商品卡片沿用现有横向卡片基础，按参考图调整图片比例、文字层级、副标题、销量、标签、价格和优惠差额。
- 该目录页移除当前“综合/销量/价格/新品”排序栏。独立搜索页和普通商品列表页继续保留，不删除搜索能力。

分类菜单来自真实分类树，不硬编码参考小程序的分类名称。一级分类显示在左侧；直接子分类显示在横向菜单。若存在三级分类，其商品归入最近的二级祖先分区，三级不新增一层菜单。

无二级分类的一级分类使用自身作为唯一内容分区。筛选后只展示包含匹配商品的分类；若当前高亮分类消失，回退到第一个仍存在的分类。

### 7.2 双向滚动联动

- 点击一级菜单：右侧滚到该一级标题，立即更新一级高亮，并保证左侧选项可见。
- 手动滚动右侧：当内容越过标题锚点，更新一级高亮。
- 点击二级菜单：右侧滚到对应二级标题，立即更新二级高亮。
- 手动滚入新二级分区：更新二级高亮，并让横向菜单自动滚到可见位置。
- 点击触发程序滚动期间锁定目标高亮；到达目标锚点后恢复位置计算，防止中途经过其他分区时闪烁。
- 数据加载、筛选切换、图片尺寸稳定后重新测量锚点。
- 图片使用固定宽高和占位背景，加载失败不改变列表高度。

优先使用小程序原生 `scroll-view`、`scroll-into-view`、滚动事件和现有 Vue 状态，不增加滚动库。活动分区由一个独立纯函数根据锚点和当前滚动位置计算，便于留下最小自检。

### 7.3 疼痛友好筛选

筛选是真实业务能力，不做假开关：

- 商品表新增布尔字段 `painFriendly`，默认关闭。
- 管理端商品新增/编辑表单提供开关，并在列表中可识别该属性。
- C 端目录接口接受可选 `painFriendly=true`。
- 开关成功后重新请求整个目录并重新测量锚点。
- 请求失败时保留旧目录、恢复开关原值并显示错误提示。
- 匹配数量和二级菜单数量均以筛选后的服务端结果为准。

### 7.4 目录接口

在现有商品模块增加一个适合连续目录的 C 端接口，不让前端按每个分类并发请求：

```ts
interface ProductCatalog {
  groups: Array<{
    id: string;
    name: string;
    sections: Array<{
      id: string;
      name: string;
      total: number;
      products: ProductCard[];
    }>;
  }>;
}
```

- 分类按后台 `sort` 排序。
- 商品按现有默认顺序排序。
- 有二级分类时，每个二级分类聚合其所有后代分类商品。
- 无二级分类时，一级分类生成一个同名 section。
- 过滤掉空 section 和空 group。
- 卡片返回现有字段，并补齐 `subTitle` 与 `painFriendly`；优惠金额由前端用 `originalPrice - price` 展示，不新增冗余字段。

当前一次返回全部上架商品，保证锚点稳定并减少请求复杂度。商品目录超过 200 个时，再将接口升级为分区懒加载；当前不提前实现分页锚点占位系统。

## 8. 异常处理

- 首次目录请求失败：在右侧内容区显示错误态和重试按钮。
- 筛选请求失败：保留旧数据并恢复开关，不清空页面。
- 无匹配商品：保留整体页面骨架，在右侧显示悦己空状态。
- 分类或商品在刷新后消失：清理失效 ID，选择最近仍存在的分区。
- 图片加载失败：显示固定比例占位，不移动后续锚点。
- 订单等提交操作：请求期间禁用重复提交；金额和状态始终以服务端结果为准。

## 9. 验收标准

### 9.1 视觉

- 以 750rpx 为设计基准，在 375px 和 430px 逻辑宽度下均无错位、遮挡或横向溢出。
- 关键布局宽高、边距和吸顶位置与参考图的换算误差控制在约 `4rpx`。
- 字号、字重、行高、截断、图片比例和裁切方式逐项对比。
- 微信端字体栅格化导致的细微像素差异不作为缺陷。
- 页面最终使用悦己品牌素材和真实数据，因此图片内容与文字长度不要求与参考图相同，但布局边界必须覆盖真实极端数据。

### 9.2 交互

- 点击一级/二级菜单准确滚到目标分区。
- 手动滚动能稳定更新两个菜单的高亮，无来回闪烁。
- 二级高亮项始终自动保持在横向可视区域。
- 筛选切换、空数据、重新加载和图片失败后，菜单与锚点仍正确。
- 页面返回、下拉刷新、列表底部和商品详情跳转符合业务流程。

### 9.3 工程检查

- 滚动分区计算留下一个不依赖新测试框架的最小可运行自检。
- 小程序运行 `pnpm type-check` 和 `pnpm build:mp-weixin`。
- 后端运行商品模块相关测试与构建检查。
- 管理端运行现有类型检查或构建命令。
- 微信开发者工具验证本批主链路，并提供参考图与实现图对比。
