# 确认订单优惠券与积分抵扣设计

日期：2026-08-29

## 目标与范围

在现有确认订单页接入服务端已经具备的优惠券和积分试算能力。支持选择一张优惠券、选择不使用优惠券，以及默认开启积分抵扣。优惠券使用规则展开、领券、积分手工输入和积分流水不在本次范围。

## 页面与交互

- 确认页增加“优惠券”行，展示可用数量和当前优惠金额；点击后从底部弹出可用券列表。
- 弹层默认选中优惠金额最高的一张，提供“不使用优惠券”，不展示使用规则。
- 确认页增加“积分抵扣”行和开关。开关默认开启，使用服务端返回的本单最高可用积分；关闭时使用 0 积分。
- 选择优惠券后重新计算积分上限；若积分保持开启，则继续使用新的最高可用积分。
- 金额明细分别展示会员优惠、优惠券优惠、积分抵扣和应付金额。

## 数据流

1. 页面加载商品或购物车来源后，并行请求可用优惠券与不使用权益的基础试算。
2. 默认选择可用券列表第一项；调用 `POST /app/order/quote` 试算该券，再用返回的 `maxUsablePoints` 发起最终试算。
3. 切换优惠券或积分开关时，始终重新调用服务端试算，不在前端计算优惠金额。
4. 创建订单时提交当前 `memberCouponId` 和服务端确认后的 `pointsUsed`。

## 接口与类型

- `POST /app/order/available-coupons`：返回当前订单可用券，按优惠金额降序展示。
- `POST /app/order/quote`：返回 `couponAmount`、`pointsUsed`、`pointsDeduct`、`maxUsablePoints` 和 `payAmount`。
- 沿用现有 `OrderForm`，仅补充可用券响应类型与 API 方法，不新增营销 Store。

## 状态与错误处理

- 切换权益期间禁用重复操作，并显示轻量加载状态。
- 重新试算失败时保留上一次成功的券、积分和金额结果，并提示用户重试。
- 没有可用券时优惠券行显示“暂无可用”；没有可用积分时开关关闭且禁用。
- 创建订单仍以服务端最终校验为准；券失效、余额变化或上限变化直接展示服务端错误。

## 验收

- 有券时默认选择优惠金额最高的一张，可切换其他券或不使用。
- 积分默认开启，使用当前券下的本单最高可用积分；关闭后抵扣清零。
- 切券后积分上限和应付金额随服务端试算更新。
- 提交订单携带当前券和积分，服务端订单金额与确认页最后一次试算一致。
- H5 在 `375×812`、`430×932` 正常展示，并通过现有 `pnpm verify:ui`。
