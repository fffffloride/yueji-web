# 小程序拼团详情设计

日期：2026-08-29  
状态：已确认

## 1. 目标

按蓝湖 07「拼团详情」、09「组团规则」、10「组团入口」还原悦己小程序拼团详情页。参考稿只决定布局、层级和交互，主题色、商品、价格及规则文案均使用悦己现有主题与真实业务数据。

本批不实现蓝湖 08「组团列表」，不增加分享奖励、团长权益、虚拟成团或复杂团购玩法。

## 2. 页面映射

三张设计稿复用现有 `pages-sub/marketing/group-buy-detail/index` 路由：

- 无 `groupId`：展示 10「组团入口」状态，可发起新团，并展示当前活动可加入的团。
- 有 `groupId`：展示 07「拼团详情」状态，显示团状态、成员支付进度和参团操作。
- 09「组团规则」：作为详情页下方规则区，不新增独立路由。

活动列表页不在本批实现；详情页继续接收 `activityId`，开团或参团成功后使用返回的 `groupId`、`orderId` 和 `orderNo` 进入支付链路。

## 3. 视觉结构

### 3.1 顶部活动区

- 页面标题为“拼团活动”。
- 顶部浅绿色活动区展示真实活动名称、商品名、SKU 名、商品图、原价和拼团价。
- 蓝湖粉色强调统一映射为现有墨绿主题变量；价格继续使用项目价格色。
- 不复制参考项目的 E-BOX、8 折、营养方案或品牌图片。

### 3.2 拼团流程卡

复用 07/09/10 的三段横向流程结构，文案改为：

1. 支付开团：创建拼团订单并完成支付。
2. 邀请参团：其他会员加入并完成支付。
3. 人数满员：已支付人数达到要求后成团。

流程节点使用现有图标或纯 CSS 圆形节点，不新增图片资源和依赖。

### 3.3 入口状态

- 主按钮为“发起拼团”，需要会员登录。
- 展示活动结束倒计时、成团人数和拼团价。
- 活动详情返回的可加入团最多 20 个，列表展示已支付人数、占位人数、目标人数和截止时间；仍有名额时可直接参团。
- 无可加入团时只保留发起拼团按钮和规则区，不制造空白占位卡。

### 3.4 团详情状态

- 展示“还差 N 人成团”或“拼团成功/拼团失败”。
- 成员区按目标人数渲染成员头像；已有成员显示头像、昵称和待支付/已支付/已退款/已取消状态，空位使用虚线占位。
- 拼团中且仍有名额时显示“参与拼团”；当前订单待付款时显示“继续支付”。
- 成功或失败为终态，不显示参团按钮；失败状态说明已付款订单由服务端自动退款，页面只重新请求状态，不做本地退款推断。

### 3.5 规则区

规则文案依据当前服务端能力：

1. 每个活动绑定一个商品规格，拼团价不叠加会员折扣、优惠券或积分。
2. 开团或参团都会创建一笔待付款订单，待付款和已付款成员共同占用名额。
3. 仅已支付人数计入成团人数，达到活动要求后自动成团。
4. 每团截止时间以页面倒计时为准；超时未成团时，未付款订单自动取消，已付款订单原路退款。
5. 同一会员不能重复加入同一拼团；活动结束、团已满或库存不足时不能开团或参团。

## 4. 数据与接口

新增 `src/api/group-buy/index.ts` 与 `types.ts`，只封装现有接口：

- `GET /app/group-buy/activities/:id`
- `GET /app/group-buy/groups/:id`
- `POST /app/group-buy/groups`
- `POST /app/group-buy/groups/:id/join`

页面金额均为整数分并通过 `formatPrice` 展示。时间、人数和状态以接口返回值为准，不在前端提前改变团状态。

开团/参团响应中的 `orderId` 交给现有 `PayAPI.create` 创建支付单，随后跳转支付结果页。支付结果页接受可选 `groupId`，支付后提供“查看拼团进度”入口回到本页。

## 5. 状态与异常处理

- 首次加载：显示通用加载态。
- 活动或团请求失败：显示网络错误态与重试按钮。
- 活动不可用：展示服务端错误，不允许继续提交。
- 开团/参团：请求期间禁用按钮，防止重复创建订单。
- 未登录：复用 `navigate(..., { requireAuth: true })` 登录回跳。
- 倒计时归零或页面重新显示：重新请求团详情，由服务端决定成功、失败或仍在进行。
- 图片失败：使用固定比例的悦己文字占位，不改变布局高度。

## 6. 最小实现范围

预计只修改：

- 拼团详情页。
- 拼团 API 与类型。
- 支付结果页的可选拼团回跳。
- 一个无框架的倒计时/人数状态自检，并加入 `verify:ui`。

不新增通用组件；只有实际出现第二个调用方时再抽取流程卡或成员卡。

## 7. 验收标准

- 375×812 与 430×932 两个视口无横向溢出、底部按钮遮挡或长文案错位。
- 入口状态能发起拼团并进入支付；可加入团能参团并进入支付。
- 支付结果能返回对应团详情，页面显示服务端最新支付人数和团状态。
- 拼团中、成功、失败、无可加入团、请求失败和重复提交均有明确表现。
- 页面颜色、按钮、间距和卡片层级贴近 07/09/10，品牌与业务文案全部替换为悦己内容。
- 通过新增最小自检、`pnpm verify:ui` 和微信小程序构建；微信开发者工具与真机验证保留为发布前人工门槛。
