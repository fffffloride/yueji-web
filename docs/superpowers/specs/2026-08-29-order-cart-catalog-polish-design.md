# 订单、购物车与商品目录细节修正设计

日期：2026-08-29  
状态：待书面确认

## 1. 目标

完成三处已确认的界面与交互修正：

- 订单确认页的备注输入框默认仅占一行，输入多行时自动增高。
- 购物车商品勾选框垂直居中；点击商品图片或商品信息进入对应详情页，删除和数量操作不触发跳转。
- 商品目录固定置顶“今日主推”“明星单品”“产品上新”三个分组，并移除商品名称右侧的标签展示。

保持现有真实接口、金额单位、路由、购物车操作和疼痛友好筛选不变，不新增依赖。

## 2. 订单确认页

备注继续使用现有 `wd-textarea`，只启用组件原生的自动高度能力。空内容时按单行高度展示；换行或内容自然换行后随内容增高，不设置固定高度，也不改联系人、手机号和备注字段的提交逻辑。

## 3. 购物车

- 只让商品卡片内的勾选框垂直居中，不改变图片、文字、价格和数量控件的布局规则。
- 商品图片和名称、规格、失效提示组成的商品信息区可点击，使用现有 `navigate()` 跳转到 `RoutePath.PRODUCT_DETAIL`，参数为购物车项已有的 `productId`。
- 勾选框、删除按钮和数量控件保持独立操作区，不把整张卡片设为点击目标，避免事件冒泡导致误跳转。
- 商品失效时仍可按 `productId` 尝试打开详情；若商品已下架，由现有详情页错误态处理。

## 4. 商品目录固定分组

固定分组由后端 `app/product/catalog` 生成并置于普通分类之前，前端继续统一渲染 `groups`：

| 固定分组 | 商品规则          |
| -------- | ----------------- |
| 今日主推 | `tags` 包含“推荐” |
| 明星单品 | `tags` 包含“热卖” |
| 产品上新 | `tags` 包含“新品” |

- 同一商品可以进入多个固定分组。
- 固定分组内沿用目录现有的商品顺序：后台 `sort` 升序，再按销量降序。
- 后端为固定分组返回明确的 `fixed: true` 标识；普通分类不设置或返回 `false`。
- 三个固定分组始终返回。没有匹配商品时保留入口和空 section，前端显示“暂无商品”。
- 疼痛友好筛选开启后，固定分组只保留疼痛友好商品，但固定入口和空 section 仍保留；普通分类继续过滤空分组。
- 继续复用后台已有“推荐 / 热卖 / 新品”标签维护能力，不新增数据库字段或后台表单。

## 5. 商品卡片

共享 `YjProductCard` 不再渲染商品名称右侧的首个标签，也删除对应无用样式。`product.tags` 字段继续保留，供固定分组和其他业务使用；副标题、销量、疼痛友好、价格及优惠信息不变。

## 6. 异常与边界

- 固定分组无匹配商品时只显示局部空提示，不让目录整体进入空状态。
- 目录首次加载失败继续使用现有错误态与重试按钮。
- 长商品名仍使用现有单行截断；移除右侧标签后可使用完整剩余宽度。
- 购物车详情跳转不改变当前购物车数据和勾选状态。

## 7. 验收

- 在 `375×812` 和 `430×932` 下检查确认页、购物车和商品目录，无错位、遮挡或横向溢出。
- 验证空备注为单行高度，输入多行后高度增长。
- 验证购物车图片与商品信息可进入正确详情；勾选、删除、改数量均不误跳转。
- 验证三个固定分组顺序、标签映射、重复商品、空分组和疼痛友好筛选。
- 验证商品名称右侧不再显示标签，下方疼痛友好等信息保留。
- 运行后端商品目录相关测试和构建，并运行小程序 `pnpm verify:ui`。
