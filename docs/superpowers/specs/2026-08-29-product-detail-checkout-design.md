# 商品详情与最小交易闭环设计

日期：2026-08-29  
状态：已确认

## 1. 目标

以用户提供的五张商品详情参考图为布局依据，完成悦己商品详情页，并打通商品详情、购物车、确认订单、创建订单、开发环境 Mock 支付和支付结果的最小真实链路。

参考图只决定页面层级、信息密度、间距和交互位置；商品图片、名称、说明、价格和规格全部使用悦己后台数据，不复制参考产品的品牌素材或文案。

## 2. 本轮范围

### 2.1 商品详情

- 保留现有路由 `pages-sub/product/detail/index`，使用商品详情真实接口。
- 顶部采用沉浸式媒体区和返回按钮，展示后台轮播图或视频；没有媒体时显示固定高度占位，不让页面塌陷。
- 价格区展示当前 SKU 售价、原价和两者的实际差额。没有原价差时不显示优惠文案，不把售价称为券后价或到手价。
- 信息区展示商品名、副标题、销量和后台标签；没有的数据整块隐藏。
- 规格区展示所有启用 SKU、售价、库存和选中态；缺货 SKU 可见但不可选，首次默认选择第一个有库存 SKU。
- 项目介绍直接渲染后台 `detail` 富文本。
- 购买说明只展示后台 `usageNote`；不把参考图中的购买、退款或医疗声明写死到前端。
- 固定底栏提供购物车入口、加入购物车和立即购买。未选规格、全部缺货或请求提交中时禁用相应操作。

### 2.2 购物车最小接入

- 新增小程序购物车 API 映射，接入 `/api/v1/app/cart` 的查询、新增、改数量、改选中和删除。
- 现有 Pinia 购物车改为服务端数据缓存，不再把本地持久化数组作为订单依据。
- 加购成功后重新拉取购物车，保证购物车 Tab 徽标和服务端一致。
- 购物车页沿用现有悦己样式完成最小真实列表、数量、选择、失效提示、删除和去结算；本轮不按商品详情参考图猜测购物车视觉稿。

### 2.3 确认订单

- 保留现有路由 `pages-sub/order/confirm/index`。
- 立即购买通过查询参数传递 `skuId` 和数量；购物车结算传递已选 `cartIds`，不新增一次性草稿 Store。
- 页面加载时重新读取商品或购物车数据，并调用 `/api/v1/app/order/quote` 获取服务端试算。
- 展示商品、规格、数量、商品总额、会员折扣、总优惠和应付金额；为零的优惠项不展示。
- 联系人默认使用会员昵称，手机号默认使用会员手机号；提交前校验联系人和手机号，允许填写备注。
- 提交调用 `POST /api/v1/app/order`。金额、库存、优惠和订单状态只采信服务端结果；提交中禁止重复点击。

### 2.4 支付与结果

- 非零元订单创建后调用 `/api/v1/app/payment` 创建或复用支付单，并进入支付结果页。
- 开发环境只使用服务端已有 `mock-confirm`；不伪造微信支付参数，也不声称真实微信支付已经完成。
- 零元订单由服务端自动推进状态，直接进入成功结果。
- 支付结果页查询本人支付单，展示处理中、成功或失败，并允许处理中状态重试查询；开发环境提供明确的“模拟支付”动作。
- 本轮结果页只提供返回首页，不提前实现尚无参考图的订单详情视觉改造。

## 3. 明确不做

- 分期免息。
- 商品详情页领券弹层、可领取优惠券列表和使用规则展开。
- 返积分预估。
- 咨询客服、机构或门店选择、医生选择及预约绑定。
- 参考产品的购买须知、退款公式、未成年人声明和其他静态规则。
- 收藏、分享、相关推荐和第三方品牌图片。
- 真实微信支付；该能力继续留到阶段 9。
- 为本轮新增商品、订单、支付字段，或修改管理端表单。

## 4. 页面结构与视觉映射

### 4.1 商品详情入口态

1. 沉浸式轮播媒体区，左上角为安全区内的返回按钮。
2. 价格带，使用悦己墨绿主题表达当前售价和原价差，不复制参考图荧光绿与第三方品牌条。
3. 商品信息：名称、副标题、销量、标签。
4. 规格选择：选中 SKU、价格、库存；下方展示当前选择摘要。
5. 项目介绍：后台富文本原样展示，并约束图片最大宽度为页面宽度。
6. 购买说明：后台 `usageNote` 非空时展示。
7. 固定交易底栏，处理底部安全区。

参考图宽度按 `750 / 截图宽度` 归一为 rpx。最终校准重点是媒体区比例、价格带高度、内容左右留白、标题层级和底栏高度；真实商品图片比例不一致时使用固定容器与 `aspectFill`，不拉伸图片。

### 4.2 确认订单与支付结果

这两个页面没有参考图，仅复用 `YjPage`、现有主题变量、卡片、表单和固定底栏，优先保证真实链路、状态反馈和可用性，不额外创造营销模块。

## 5. 数据流

### 加入购物车

1. 未登录时跳转登录，并携带当前商品详情回跳地址。
2. 校验已选择且有库存的 SKU。
3. 调用购物车新增接口；商品详情本轮固定购买一件，后续可在购物车修改数量。
4. 重新读取服务端购物车并刷新徽标。

### 立即购买

1. 未登录时先登录并回到详情页。
2. 携带 `skuId` 和固定数量 `1` 进入确认订单。
3. 确认页读取真实商品数据并调用订单试算。
4. 用户确认联系人信息后创建订单。
5. 零元订单直接展示成功；非零元订单创建支付单后进入支付结果。

### 购物车结算

1. 购物车提交已选且有效的 `cartIds`。
2. 确认页重新读取购物车，并使用同一订单试算和创建流程。
3. 创建成功后由服务端删除已结算购物车项，前端重新拉取购物车。

## 6. 错误与边界状态

- 商品详情首次请求失败：显示错误态和重试按钮；商品不存在或下架时不显示交易底栏。
- 轮播为空或图片失败：显示固定尺寸占位，不改变后续内容位置。
- SKU 全部缺货：保留规格信息，禁用加入购物车和立即购买。
- 加购、试算、创建订单、创建支付单和 Mock 支付均防重复提交。
- 服务端返回库存不足、商品下架或会员折扣变化时，直接展示服务端消息并重新试算，不做本地乐观修正。
- 登录失效继续由现有请求层统一清 Token 并跳转登录。
- 购物车中的失效商品可删除但不能选中或结算。
- 支付查询失败保留当前页面和重试入口，不把网络错误误判为支付失败。

## 7. 实现边界

- 复用 `YjPage`、`RoutePath`、`navigate()`、主题变量、请求封装和 Wot Design 组件。
- 不新增依赖，不修改服务端和管理端；现有三端接口字段已覆盖本轮需求。
- 商品详情、购物车、订单和支付各自保留在现有 API/页面目录，不建立通用交易框架。
- 立即购买和购物车两种订单入参使用一个小型纯函数归一化，并留下一个无测试框架的可运行自检，覆盖来源解析和非法空参数。

## 8. 验收标准

### 视觉与交互

- 在 `375×812` 和 `430×932` 两种视口下无横向溢出、底栏遮挡或安全区错位。
- 商品详情入口、中部富文本、底部说明、SKU 选中、SKU 缺货、媒体空态和请求失败态均可验证。
- 参考图能映射到现有字段的区域保持相同视觉层级；被明确排除的区域不留下空壳入口。

### 真实链路

- 登录后可完成：商品详情 → 加入购物车 → 购物车结算 → 服务端试算 → 创建订单。
- 登录后可完成：商品详情 → 立即购买 → 服务端试算 → 创建订单 → Mock 支付 → 成功结果。
- 库存不足、商品或 SKU 下架、重复提交、空购物车和支付查询失败均有明确反馈。

### 工程门槛

- 新增的交易来源纯函数自检通过。
- `pnpm verify:ui` 通过，包含 ESLint、Stylelint、类型检查、现有 UI 自检、H5 构建和微信小程序构建。
- H5 完成双尺寸真实交互验收；微信开发者工具和真机仍作为发布前人工门槛。
- 本轮实现独立提交，不包含临时参考图、构建产物或无关文件。
