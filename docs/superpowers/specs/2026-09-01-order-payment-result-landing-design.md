# 订单支付结果落地页设计

## 目标

在现有 `pages-sub/order/pay-result/index.vue` 内完成支付成功、支付失败落地页，让用户明确知道支付结果和下一步操作。

- 普通订单支付成功后，主操作为「去预约」。
- 拼团订单支付成功但尚未成团时，主操作为「查看拼团进度」，不显示「去预约」。
- 支付失败后不提供当前不可用的「重新支付」，主操作为「查看订单」。
- 保留现有待支付、查询中、退款和查询异常状态，不新建页面。

## 视觉方向

采用已确认的 A「安心服务型」。页面保持克制、清晰，使用现有主题变量，不引入图片或新依赖。

### 结构

1. 顶部状态区：圆形状态图标、结果标题、两行以内说明。
2. 中部信息卡：订单号、金额、支付时间或支付状态。
3. 底部操作区：一个主按钮、一个次按钮、一个弱化文字入口。

### 成功态

- 绿色圆形对勾。
- 标题：「支付成功」。
- 普通订单说明：「项目已购买成功，选择合适时间，到店开启变美体验」。
- 信息卡展示订单号、实付金额、支付时间。
- 普通订单按钮顺序：
  1. 主按钮「去预约」→ `RoutePath.APPOINTMENT`
  2. 次按钮「查看订单」→ `RoutePath.ORDER_DETAIL`
  3. 文字入口「返回首页」→ `RoutePath.HOME`
- 拼团订单按钮顺序：
  1. 主按钮「查看拼团进度」→ `RoutePath.GROUP_BUY_DETAIL`
  2. 次按钮「查看订单」→ `RoutePath.ORDER_DETAIL`
  3. 文字入口「返回首页」→ `RoutePath.HOME`

### 失败态

- 红色圆形感叹号。
- 标题：「支付失败」。
- 说明：「本次支付未完成，订单仍为待付款，请在订单中查看后续状态」。
- 信息卡展示订单号、应付金额、支付状态。
- 按钮顺序：
  1. 主按钮「查看订单」→ `RoutePath.ORDER_DETAIL`
  2. 次按钮「返回首页」→ `RoutePath.HOME`
  3. 微信原生客服入口「遇到问题？联系客服」；不自建客服页面。

## 状态与数据来源

页面继续以服务端支付状态为唯一事实来源。

| 条件                           | 展示状态          | 主操作                             |
| ------------------------------ | ----------------- | ---------------------------------- |
| `success=1` 的零元订单         | 支付成功          | 普通订单去预约                     |
| 支付单 `SUCCESS`，无 `groupId` | 支付成功          | 去预约                             |
| 支付单 `SUCCESS`，有 `groupId` | 支付成功          | 查看拼团进度                       |
| 支付单 `FAILED`                | 支付失败          | 查看订单                           |
| 支付单 `PENDING`               | 等待支付 / 查询中 | 刷新支付结果；开发环境保留模拟支付 |
| 支付单 `REFUNDED`              | 已退款            | 查看订单                           |
| 查询失败                       | 暂时无法确认      | 刷新支付结果                       |

不根据页面停留时间推断成功或失败，不在前端提前变更订单状态。

## 参数与导航

支付结果页需要稳定获得 `orderId`，用于「查看订单」。

- 普通付费订单：支付查询结果已有 `payment.orderId`，同时允许入口显式传入 `orderId`。
- 零元订单：确认页跳转时必须补传 `orderId`。
- 拼团订单：拼团支付跳转时补传 `orderId`。
- `orderId` 缺失时不显示「查看订单」，不拼接无效详情链接。
- 预约为 TabBar 页面，继续通过统一 `navigate()` 使用 `switchTab`。

## 实现范围

最小改动涉及：

- `src/pages-sub/order/pay-result/index.vue`：重排状态区、信息卡和动作区，增加预约、订单详情与客服动作。
- `src/pages-sub/order/confirm/index.vue`：跳转支付结果页时补传 `orderId`。
- `src/pages-sub/marketing/group-buy-detail/index.vue`：跳转支付结果页时补传 `orderId`。

不抽取新组件，不增加新状态管理，不增加依赖。

## 错误与边界

- 查询支付结果失败时保留当前可用信息，展示错误说明和刷新按钮。
- 支付失败不展示「重新支付」：当前后端同一订单已有失败支付单时不会创建新的支付尝试。
- 拼团支付成功不代表已经成团，因此不显示「去预约」。
- 零元订单没有支付单，金额使用订单跳转参数无法可靠补齐时不展示金额行，只展示订单号和成功结果。
- 所有状态均同时使用图形、标题和文字表达，不仅依赖颜色。

## 验证

- 普通订单支付成功：显示「去预约」，可进入预约 Tab。
- 拼团订单支付成功：显示「查看拼团进度」，不显示「去预约」。
- 零元订单成功：无需支付单也能显示成功态和预约按钮。
- 支付失败：显示失败态、查看订单和返回首页，不显示重新支付。
- 待支付、查询失败、已退款和开发环境模拟支付不回归。
- 运行 `pnpm type-check` 与 `pnpm build:mp-weixin`。

## 后续需求：预约绑定订单

本次仅记录，不在本次支付结果页改造中实现。

后续预约需要支持绑定订单，使「去预约」能携带当前订单进入预约流程。届时服务端预约创建接口需接收 `orderId`，校验订单归属、已支付且可预约，并避免同一订单产生冲突预约；小程序预约页需展示订单/项目摘要并随预约提交绑定关系。具体数据结构、可重复预约规则和解绑/改期规则另开设计，不在本次预埋字段或占位逻辑。

## 不在本次范围

- 支付失败后的重新支付能力。
- 预约与订单的真实绑定。
- 订单列表、订单详情占位页的完整实现。
- 支付驱动或服务端订单状态机调整。
