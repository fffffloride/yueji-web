# 消费会员等级与会员中心设计

日期：2026-09-02  
状态：已确认

## 1. 目标

把“我的”页会员卡从静态占位改为真实消费会员等级，并完成现有“会员中心”空壳页。等级、累计消费和折扣均以后端配置为准；小程序不自行判定等级或计算订单优惠。

默认等级如下：

| 等级        | 累计完成订单实付 |   折扣 |
| ----------- | ---------------: | -----: |
| L1 普通会员 |           0 元起 | 不打折 |
| L2 白银会员 |         5 万元起 |   9 折 |
| L3 黄金会员 |        10 万元起 |   8 折 |
| L4 白金会员 |        20 万元起 |   7 折 |

白金会员为最高等级且不设上限；累计消费超过 50 万元后仍保持白金会员 7 折。

## 2. 现状与复用范围

- 后端已有 `member_level`、会员 `total_spent`、订单完成后升级和订单等级折扣逻辑。
- 管理端已有“会员等级”增删改查，不新增管理页面。
- C 端已有 `/api/v1/app/marketing/account`，当前返回积分、累计实付和当前等级。
- 小程序“我的”页会员卡仍读取 `src/mocks/mine.ts`；`pages-sub/user/member/index` 仍为空壳。
- 路由、鉴权、金额单位和订单计价顺序保持不变。

## 3. 数据与后台默认配置

新数据库的阶段 5 初始化脚本默认写入四个等级，门槛分别为 `0`、`5_000_000`、`10_000_000`、`20_000_000` 分，折扣万分比分别为 `10000`、`9000`、`8000`、`7000`。

既有数据库增加可重复执行的增量 SQL：按门槛补齐缺失等级，不覆盖管理员已经配置的同门槛记录。这样保留后台配置权，也避免部署时制造重复门槛。

等级仍采用“达到下限后生效”的现有模型。最高启用等级自然无上限，不新增结束金额字段。

## 4. C 端账户数据

扩展现有 `/api/v1/app/marketing/account`，不新建会员中心专用接口。响应在兼容现有字段的基础上增加：

```ts
interface PointsAccount {
  points: number;
  totalSpent: number;
  level: {
    id: string;
    name: string;
    discountRate: number;
    code: string; // L1、L2……，按启用等级门槛升序生成
    thresholdAmount: number;
  } | null;
  nextLevel: {
    id: string;
    name: string;
    code: string;
    thresholdAmount: number;
  } | null;
  levels: Array<{
    id: string;
    name: string;
    code: string;
    thresholdAmount: number;
    discountRate: number;
  }>;
  rule: PointsRule;
}
```

后端一次读取全部启用等级并按门槛升序排列，以同一份数据解析当前等级、下一等级和 `L1–Ln`。进度由小程序使用服务端返回的累计实付与相邻门槛做纯展示计算；当前等级和折扣仍完全取服务端结果。

## 5. 小程序页面

### 5.1 “我的”页会员卡

- 登录后请求现有账户接口；未登录不请求。
- 会员卡左侧显示真实等级名称，例如“普通会员”。
- 右侧原“Lock待解锁 0/1”改为当前等级编号，例如 `L1`，保留右箭头。
- 进度条表示从当前等级门槛到下一等级门槛的完成比例；最高等级显示满进度。
- 点击会员等级区域进入现有 `RoutePath.USER_MEMBER`。
- 预约统计等其他静态区域不在本次范围内。

### 5.2 会员中心

会员中心复用同一个账户请求，展示：

1. 当前等级名称、等级编号和折扣；
2. 累计完成订单实付金额；
3. 距离下一等级所需金额及升级进度；最高等级显示“已达最高等级”；
4. 全部启用等级的名称、门槛和折扣列表，并突出当前等级。

页面继续使用现有 `YjPage`、主题变量、SCSS/BEM 和金额格式化工具，不增加组件库或通用抽象。

## 6. 状态与错误处理

- 未登录：沿用现有鉴权跳转进入登录页。
- 首次加载：显示现有加载组件。
- 请求失败：会员中心显示网络错误态和“重新加载”；“我的”页保留卡片结构并显示占位符，不伪造等级。
- 后台没有任何启用等级：账户接口返回 `level: null`、`nextLevel: null` 和空列表；页面显示“暂无可用等级”。
- 后台停用或调整等级后：再次进入页面重新请求，不持久化等级配置。
- 升级进度限制在 `0–100%`，避免异常数据造成布局溢出。

- 不把后台等级配置复制成前端业务判断常量。
