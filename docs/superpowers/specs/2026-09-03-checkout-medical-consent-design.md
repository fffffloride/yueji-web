# 确认订单就诊知情同意设计

## 目标

用户提交订单前必须阅读并同意《用户就诊告知及知情同意书》，协议内容由后台富文本配置并发布。

## 协议配置

- 在现有协议类型中新增 `MEDICAL_INFORMED_CONSENT`，显示名称为“用户就诊告知及知情同意书”。
- 复用现有后台协议列表、富文本编辑、保存草稿和发布能力，不新增独立配置页面。
- 小程序复用现有协议详情页，根据协议类型加载并展示已发布的标题与富文本正文。
- 初始化 SQL 增加该协议的默认记录，实际业务内容由运营人员在后台编辑并发布。

## 确认订单交互

- 在确认订单页的金额汇总与底部操作栏之间展示未勾选的同意项：“我已阅读并同意《用户就诊告知及知情同意书》”。
- 点击协议名称进入协议详情页；返回后保留当前订单填写状态和勾选状态。
- “立即支付”“好友代付”和 0 元订单的“确认订单”统一执行协议校验。
- 用户未勾选就提交时，弹出提示：“购买商品，请先阅读并同意”，操作为“我再想想”和“同意”。
- 点击“我再想想”关闭弹窗并停留当前页；点击“同意”自动勾选，并继续执行用户刚才选择的提交方式。
- 协议校验发生在创建订单之前，未同意时不得产生订单或支付单。

## 数据与错误处理

- 页面加载结算数据时同步读取当前已发布的协议，界面标题使用后台返回的标题。
- 协议正在加载时禁用提交；协议未发布或加载失败时阻止提交，并提示“协议暂不可用，请稍后重试”。
- 勾选状态仅保留在当前确认订单页面，不作为全局偏好，也不跨订单复用。
- 本次不新增订单协议快照、历史版本和同意记录；如后续合规审计要求追溯具体版本，再扩展订单存档。

## 验证

- 增加一个最小可运行检查，覆盖未勾选阻止提交、弹窗同意后继续原提交方式、协议不可用时阻止提交。
- 验证三种入口：立即支付、好友代付、0 元确认订单。
- 验证协议标题可跳转、富文本可正常展示，后台可保存并发布新增协议类型。
- 执行 Web、后台管理端和服务端现有的类型检查或构建检查。
