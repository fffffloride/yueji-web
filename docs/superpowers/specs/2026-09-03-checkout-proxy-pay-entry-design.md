# 结算页好友代付入口设计

## 目标

用户在确认订单时即可选择本人支付或好友代付，不必先取消支付再去待付款列表操作。

## 交互

- 应付金额大于 0 时，结算页底部显示次按钮“好友代付”和主按钮“立即支付”。
- 应付金额为 0 时只显示“确认订单”，不显示好友代付。
- 订单已经创建但尚未支付时，按钮显示“好友代付”和“继续支付”。
- 待付款订单列表中的“好友代付”入口继续保留。

## 流程

两个入口复用同一套表单校验和订单创建逻辑，保证一次点击只创建一个订单：

1. 校验联系人、手机号、订单来源和试算结果。
2. 尚未创建订单时，按当前优惠券和积分结果创建订单并同步购物车。
3. 本人支付分支创建支付单并调起支付。
4. 好友代付分支直接携带 `orderId` 进入现有代付邀请页，不创建本人支付单。

用户从代付邀请页返回后，结算页保留已创建订单，可继续分享或切换为本人支付，不重复下单。

## 异常与边界

- 下单失败时停留在结算页，保留表单并允许重试。
- 代付邀请创建失败时由现有代付页展示错误和重试入口。
- 0 元订单、已支付订单和拼团订单不进入该分支；拼团使用独立支付页面。
- 提交期间两个按钮同时禁用，避免并发创建。

## 验证

- 源码检查覆盖双按钮、0 元订单分支、共用订单创建逻辑以及代付页跳转。
- 执行 `verify:ui`，覆盖类型、样式、H5 和微信小程序构建。
- 在 H5 目视验证普通待支付订单能从结算页直接进入代付邀请页。
