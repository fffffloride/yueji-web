# 统一缺省状态与积分明细修复设计

## 背景

“我的积分”显示余额 1863，但积分明细为空。本地数据库中该会员实际有 7 条有效流水。根因是营销前端接口仍按旧分页结构 `{ data, page }` 解析，而后端响应拦截器已经统一输出 `{ list, total }`，导致积分和优惠券分页数据被丢弃。

项目已经通过 `YjEmpty` 承载大部分空状态，但默认依赖 `wd-status-tip` 的 `content` 图，在当前 H5 页面没有稳定显示；少量局部区域仍直接渲染“暂无…”文本。

## 目标与边界

- 恢复积分流水并同步修复营销模块内相同的分页解析问题。
- 所有真实“数据为空”状态使用同一套悦己品牌缺省图和排版。
- 网络错误、资源不存在、未登录等状态继续保留现有语义图与操作。
- H5 与微信小程序共用同一资源，不新增依赖。

## 方案

### 分页数据

删除营销接口的旧结构转换，积分流水、可领取优惠券和我的优惠券直接使用项目统一的 `PageResult<T>`（`list`、`total`）。页面加载、分页和错误处理保持不变。

### 缺省组件

继续复用现有 `YjEmpty`，不增加第二套空状态组件：

- 默认无数据状态展示一张本地透明 PNG：绿色线稿空盒子，视觉与悦己主色一致。
- 统一主文案、可选说明文案、可选操作插槽。
- 提供默认与紧凑两种密度；二者使用相同插画、字体层级和颜色，仅尺寸与留白不同。
- 显式传入 `network`、`user` 等语义类型时，继续使用 `wd-status-tip`，避免把错误和登录状态误画成“无数据”。

### 覆盖范围

- 已使用 `YjEmpty` 的列表和卡片空状态自动获得统一样式。
- 积分页补充说明“完成消费后，积分变化会显示在这里”。
- 商品目录分组、预约时间等局部无数据文本改用紧凑模式。
- 普通表单提示中的“暂无可用”、字段回退文案和加载完成提示不属于空状态，不替换。

## 数据流与异常

页面请求营销分页接口后直接读取 `list` 与 `total`。有数据时渲染列表，无数据时渲染 `YjEmpty`；请求失败时仍进入现有 `network` 状态并保留重试入口。缺省图为本地静态资源，加载不依赖网络。

## 验证

- 用源码检查锁定营销分页结构和主要空状态入口，防止再次回退为旧结构或裸文本。
- 验证积分页能显示本地已有的 7 条流水。
- 执行项目 `verify:ui`，覆盖 ESLint、Stylelint、类型检查、现有源码检查、H5 构建和微信小程序构建。
- 在 H5 中目视检查默认、紧凑、网络错误三种状态。
